A node's name in MeshCore is normally just a label for humans — a callsign, a location, a reminder of what the hardware is. In Waev's ingest pipeline, the node name also functions as an explicit control: put the right character in it and that node's ADVERTs are dropped before they are stored, before they appear on the map, before they contribute to any count.

<p><strong>TLDR:</strong> MeshCore node naming privacy markers — ⛔, 🛑, or 🚫 in a node name — are checked in Waev's ingest path. An ADVERT from a node whose name contains any of these characters is dropped before it is written to the database or analytics, so it is not stored, mapped, or counted. The marker does not stop a connected partner feed from receiving the raw frame first, does not cover packets that carry no name, and is logged when it fires.</p>

## How to apply a marker

Open the MeshCore configuration for the node you want to opt out, and add ⛔, 🛑, or 🚫 anywhere in the node name. The rest of the name can be whatever it was before. `BASE1` becomes `BASE1 ⛔` or `⛔ BASE1` or `BASE1⛔` — all work. The marker does not need to be at the start or end; any position triggers the check.

The change takes effect on the next ADVERT from that node that Waev decodes. There is no other configuration required — no account setting, no Waev dashboard toggle. The opt-out lives in the node name.

## What happens at the ingest edge

Waev's ingest path runs three checks in order: opt-out, companion identity, and the physics gate for map lines. Before any of them, a connected partner feed receives the raw frame.

When Waev decodes an ADVERT, it reads the name field. If that name contains ⛔, 🛑, or 🚫 and the node isn't an enrolled observer, the packet is discarded before any database or analytics write. The ADVERT creates no record, puts no point on the Live Map, increments no Network Stats counter, and isn't archived for packet search. The drop is not complete: it writes a log line with the node's public key and name (Workers Logs keeps a 5% sample), and packets that carry no name are not checked — a discovery response from the node can still create a nameless node row.

The order matters. The opt-out check runs before the companion device scrub and before the topology pipeline. A marked ADVERT is not scrubbed — it is dropped. It is not the very first step, though: the partner feed, when connected, has already received the raw frame, and the packet has been decoded to read its name.

## When to use it

The most common use cases are personal or family devices that happen to be on the mesh — a companion app on a phone, a handheld carried by someone who did not sign up to be logged — and infrastructure nodes you are testing or running in a sensitive context.

For personal companion devices, Waev blanks the name and public key of a companion ADVERT by default, but keeps its device type, any GPS coordinates, and its signal metadata in analytics rows, and archives the raw frame. A privacy marker on the companion's node name keeps its ADVERTs out of the database, analytics, and the archive, with the exceptions above. [What we choose not to know](/blog/what-we-choose-not-to-know/) covers both gates in full detail.

For infrastructure nodes, the marker is a deliberate choice about visibility. A test node you are moving around to check coverage might carry a marker while you are working with it and lose the marker once it is installed permanently. A repeater at a private location might carry a marker permanently. If Waev has already mapped the node, its earlier row and position stay until the 182-hour prune.

## What the marker does not do

A privacy marker in a MeshCore node name is a convention that Waev checks in its own ingest path. It does not affect how MeshCore's firmware broadcasts the node's packets on the mesh. Other nodes on the mesh still hear those packets; if the same observer stream is also pointed at other tools, as the [never-captive stream](/blog/bring-your-own-broker/) allows, those tools still receive them. The marker controls only what Waev does with the packet when it arrives.

The check happens once, in Waev's ingest path, before the packet is written on Waev's side — it is not a broker-side setting. Two consumers sit outside it: other tools the observer also publishes to, and Waev's partner feed, a subscribe-only egress that, when a partner is connected, receives every observer's raw publishes for its entitled regions before the check runs. Each applies its own rules to what it keeps.
