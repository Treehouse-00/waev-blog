A MeshCore node's name is operator-configurable, and its prefix is a few bytes of its public key, which anyone can match by generating keys until one fits. There is nothing in the RF mesh protocol that prevents someone from setting up a node with a prefix that copies another node's. This is not a unique vulnerability — it's a property of any open, cooperative radio system. But it has direct implications for what a mesh map shows, and how much you can trust the topology it draws.

## What a node prefix is

MeshCore nodes are identified by an Ed25519 public key. An ADVERT carries the full key alongside the node's configured name; a packet that crosses repeaters records each hop as a short prefix of that repeater's key — 1 to 3 bytes — so the topology is reconstructed from a chain of these prefixes.

The path prefix is not signed. It travels in clear in the packet's path, and any node can claim any prefix its key produces.

## Why this matters for topology maps

Consider what a naive topology map does: it receives hop records from nodes on the mesh and draws edges based on what those records claim. Node A claims it heard Node B at SNR −14 dB. The map draws A→B. No verification step.

This approach has a failure mode: if a rogue or misconfigured node broadcasts a prefix that matches a legitimate node, the map draws edges to and from that prefix — edges that represent the rogue node's actual RF position, not the legitimate node's. The result is topology that looks plausible but is wrong. And a wrong map that looks confident is more dangerous than a gap that prompts you to investigate.

## How Waev handles it

Waev's topology engine grades every claimed link instead of trusting it.

The strongest source is an enrolled observer — a node you've connected to Waev's MQTT ingest. A reception it measures directly, with the sender's full key in the packet, is Proven; a link heard by two or more observers, or whose identity resolves with high confidence, is Corroborated. Repeaters are not authenticated: their ADVERT signatures are checked and recorded, but production runs that check in observe mode.

A link reconstructed from the path prefixes of a relayed packet is Inferred: plausible, but single-witness or identity-ambiguous. The default map draws it at reduced opacity, so it reads as a hypothesis, not a measurement. Any claimed link that fails the physics checks on distance and terrain is classed Rejected and left off the default map.

This is why the grading matters for spoofed prefixes specifically. A rogue node mimicking a legitimate node's prefix can still produce Inferred lines, because a prefix in a path is all an Inferred line needs; the label and the physics checks are what keep it from passing as measured. If an enrolled observer hears a node with a suspicious prefix directly, that's real information: a node with that prefix is broadcasting on your mesh, at that RF position, with that signal quality. That's worth knowing — and the Live Packets view will show it.

## What the map's silences mean

A node that's active on your mesh but absent from the Live Map is not hidden — it just hasn't been seen by an enrolled observer, or its observations haven't passed verification. That's a meaningful signal.

It tells you where your observer coverage ends. It tells you which parts of your mesh are producing traffic that Waev can't attribute to a measured reception. And it tells you to read the edges that do appear by their class: Proven and Corroborated lines are backed by observations from observers you enrolled; Inferred lines are not.

Topology maps that fill in the gaps — drawing edges from claimed or inferred connections in the same ink as measured ones — hide the distinction between what the mesh can prove and what it guesses. Waev draws Inferred lines too, at reduced opacity and under their own label; the label is what keeps that distinction visible.

---

The underlying principle here is the same one described in [how Waev reads your mesh](/blog/how-waev-reads-your-mesh/): every line on the Live Map carries its evidence class. A line whose only evidence is a path prefix says so, and a claim the physics checks refuse stays off the default map. That's [what Waev chooses not to know](/blog/what-we-choose-not-to-know/) applied to topology: show the evidence, and label what it doesn't prove.
